IK Tilt Clamp - Prevents Mario's feet from planting on near-vertical surfaces
Super Mario Sunshine GMSJ01 (JPN Rev 0)

SMS shipped with this bug. You see it on every rooftop in Delfino Plaza.
The issue: calcGroundMtx has no maximum tilt angle. On non-slippery steep
surfaces, Mario's body rotation follows the ground normal at any angle,
creating the "yoga on a cliff" pose.

Fix: After calcGroundMtx builds the rotation matrix, clamp the Y components
of the forward and right basis vectors (mGroundMtx[1][0] and [1][2]) to
+/- 0.5, limiting body tilt to ~60 degrees regardless of surface steepness.

Hook point: 0x8012F4F4 (calcGroundMtx epilogue, replaces lwz r0,0x64(r1))
Note: C2 handler clobbers r31, so 'this' is loaded from the stack save slot.

Annotated assembly:
  lwz r3, 0x5C(r1)        # load 'this' from r31 stack save slot
  lis r4, 0x3F00           # 0.5f (IEEE754: 0x3F000000)
  stw r4, 0x08(r1)         # store to scratch
  lfs f1, 0x08(r1)         # f1 = 0.5f (max tilt)
  fneg f2, f1              # f2 = -0.5f (min tilt)

  # Clamp mGroundMtx[1][0] (forward vector Y component)
  lfs f0, 0x260(r3)        # f0 = forward.y
  fcmpo cr0, f0, f1        # f0 > 0.5?
  ble+ 8                   # skip if not
  fmr f0, f1               # f0 = 0.5 (clamp high)
  fcmpo cr0, f0, f2        # f0 < -0.5?
  bge+ 8                   # skip if not
  fmr f0, f2               # f0 = -0.5 (clamp low)
  stfs f0, 0x260(r3)       # write back

  # Clamp mGroundMtx[1][2] (right vector Y component)
  lfs f0, 0x268(r3)        # f0 = right.y
  fcmpo cr0, f0, f1        # f0 > 0.5?
  ble+ 8                   # skip if not
  fmr f0, f1               # f0 = 0.5 (clamp high)
  fcmpo cr0, f0, f2        # f0 < -0.5?
  bge+ 8                   # skip if not
  fmr f0, f2               # f0 = -0.5 (clamp low)
  stfs f0, 0x268(r3)       # write back

  lwz r0, 0x64(r1)         # original replaced instruction
  nop                      # alignment padding
  ; 00000000               # Dolphin C2 block terminator
